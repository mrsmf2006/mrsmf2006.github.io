# داکر برای شروع: یک مقدمه عملی

داکر شیوه استقرار برنامه‌ها را عوض کرد. این‌ها برای شروع کافی است.

## چرا داکر؟

قبل از داکر، «روی سیستم من کار می‌کند» کابوس هر توسعه‌دهنده بود. داکر برنامه را با وابستگی‌هایش بسته‌بندی می‌کند.

## مفهوم‌های اصلی

### ۱. ایمیج
ایمیج مثل نقشه ساخت است. هرچه برای اجرای برنامه لازم است داخلش است.

### ۲. کانتینر
کانتینر نمونه در حال اجرای ایمیج است. جدا، سبک و قابل‌حمل.

### ۳. Dockerfile
دستور پخت ساخت ایمیج. یک نمونه ساده:

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]
```

## شروع

### نصب
از [docker.com](https://docker.com) داکر دسکتاپ را بگیر.

### اولین کانتینر

```bash
# Pull an image
docker pull nginx

# Run a container
docker run -p 8080:80 nginx
```

`localhost:8080` را باز کن. انجین‌اکس بالا است.

## استفاده واقعی

در اَملاین داکر را برای این‌ها به کار می‌بریم:
- **محیط توسعه.** تنظیم همه یکی است.
- **تست.** محیط تمیز سریع بالا می‌آید.
- **استقرار.** همان کانتینر از توسعه تا تولید می‌رود.

## چند عادت خوب

1. **ایمیج پایه رسمی** را مبنا بگذار.
2. **لایه‌ها را کم کن.** دستورهای RUN را جمع کن.
3. **با کاربر ریشه اجرا نکن.** امنیت اول است.
4. **`.dockerignore` بگذار.** ایمیج کوچک بماند.
5. **ایمیج را برچسب بزن.** همه‌چیز نسخه داشته باشد.

## دستورهای پرکاربرد

```bash
# List running containers
docker ps

# Stop a container
docker stop <container-id>

# Remove containers
docker rm <container-id>

# View logs
docker logs <container-id>

# Execute commands in container
docker exec -it <container-id> bash
```

## Docker Compose

برای چند کانتینر، Compose:

```yaml
version: '3.8'
services:
  web:
    build: .
    ports:
      - "5000:5000"
  redis:
    image: "redis:alpine"
```

اجرا: `docker-compose up`

## قدم بعدی

وقتی پایه راحت شد:
- کوبرنتیز برای ارکستراسیون
- شبکه داکر

- امنیت کانتینر

## جمع‌بندی

داکر مهارت پایه‌ای دواپس است. کوچک شروع کن، پروژه بساز، و کم‌کم پیچیده کن.

خودِ آینده‌ات به‌خاطر یاد گرفتن داکر ممنونت می‌شود.
